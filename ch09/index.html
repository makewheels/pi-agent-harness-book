    第9章 Skills、提示词模板与主题¶

    阅读提示 上一章讲了"重零件"扩展。本章讲三种"轻零件"：Skills（技能手册）、Prompt Templates（提示词快捷方式）、Themes（主题）。不写代码也能定制 Pi。约 7 分钟。

    不是所有定制都要写代码¶

    上一章的扩展很强大，但它要写 TypeScript。很多时候你想要的定制其实更轻：

    • 想让 Pi 记住一套做事方法 → 写本说明书就行
    • 想一键展开一段常用提示词 → 设个快捷键就行
    • 想换个顺眼的界面 → 换套喷漆就行

    这三种轻零件，分别就是 Skills、Prompt Templates、Themes。

    Skills：塞一本说明书¶

    Skill 是一个 Markdown 能力包——用自然语言写清楚"遇到某类活该怎么干"，Pi 需要时就读它。

    表9-1 Skill 的特点

    特点 说明
    纯 Markdown 不用写代码
    遵循 agentskills.io 标准 跨工具通用，不是 Pi 私有格式
    按需加载 Pi 用到才读，不占平时上下文

    你可以把它理解成给新员工的一本《XX 业务操作手册》——他不用改大脑，照着手册做就行。

    Prompt Templates：一键宏¶

    有些话你每次都要说一遍，比如"请用中文、分步骤、先给结论"。提示词模板让你把它存成一个 /名字，敲一下就展开。

    表9-2 提示词模板

    项 说明
    形式 /模板名 触发展开
    内容 一段预存的提示词，可带占位符
    场景 复用固定开场白、固定角色设定

    跟"快捷指令"一个道理：把长句子变成一个短按钮。

    Themes：换个喷漆¶

    主题改的是 Pi 终端界面的外观配色。纯属个人喜好，不影响能力。这是四种零件里最"无害"的一种。

    轻零件放在哪¶

    这三种零件和扩展一样，有自己的"家"，Pi 启动时会去扫描：

    表9-3 轻零件的存放位置

    零件 放哪 形式
    Skills 技能目录（全局或项目 .pi/skills/） 一个技能一个文件夹，里面一份 SKILL.md
    Prompt Templates 模板目录（.pi/prompts/） 一个模板一个文件
    Themes 主题目录（.pi/themes/） 一套配色一个文件

    那份 SKILL.md 就是"手册正文"——Pi 用到某类活时才去读它，所以平时不占上下文。这套发现逻辑，和第 8 章扩展的五个位置是同一套思路。

    四种零件放在一起看¶

    把上一章的扩展也算上，Pi 的四种定制件是这样分工的：

    表9-4 四种零件对比

    零件 要写代码吗 改的是什么 类比
    Extensions 要（TS） 能力/行为/UI 加新功能
    Skills 不用（Markdown） 做事方法 塞本手册
    Prompt Templates 不用 常用提示词 一键宏
    Themes 很少 外观 换喷漆

    一个清晰的梯度：从轻到重，从"改说法"到"改能力"。想要多深的定制，就用哪一档。

    阅读提示 这四种零件都能被打包分发——下一章的"零件市场"讲的就是它们怎么装进来。

    🧪 本章实验¶

    实验 9-1 ★｜分清四种零件 目标：建立分工感。 步骤：不看表，说出"想改外观/想加快捷提示/想教方法/想加能力"分别用哪种零件。 验收：四个全对。

    实验 9-2 ★★｜写一个 Skill 目标：体验"不写代码的定制"。 步骤：写一个 Markdown 技能包，告诉 Pi"回答前先给一句结论"，放到技能目录。 验收：Pi 的回答风格变了，而你一行代码没写。

    🤔 思考题¶

    1. ★ 为什么 Skill 用 Markdown 而不是代码，是个聪明的选择？
    2. ★★ "按需加载、不占平时上下文"对 Skill 意味着什么？
    3. ★★ 给一个需求"让 Pi 回答都用表格"，你会用四种零件里的哪一种？

    📝 小结¶

    • 不是所有定制都要写代码——轻零件三件套
    • Skills 是 Markdown 手册——遵循 agentskills.io，按需加载
    • Prompt Templates 是 /名字 一键宏——复用常用提示词
    • Themes 只改外观——最无害的定制
    • 四种零件从轻到重——改说法 → 改方法 → 改能力
