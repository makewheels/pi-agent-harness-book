# 第13章 组装你自己的 Pi：后记

> **阅读提示**
> 毕业设计时间。本章用 SDK 把前面学的零件拼成你自己的 agent，然后把这本书的设计智慧打包带走。约 9 分钟。

## 从"看图纸"到"自己造"

这本书前面十三章，一直在带你拆一台别人造好的车。最后一章，轮到你**自己拼一台**了。

好消息是：Pi 把零件都备好了，你要做的只是**组装**。而组装的工具，就是第 11 章提过的 SDK。

## 三块积木

用 SDK 搭一个能跑的 agent，核心就三块：

**表13-1 三块积木**

| 积木 | 代码 | 干什么 |
|---|---|---|
| 运行时 | `ModelRuntime.create(...)` | 备好模型与认证 |
| 会话 | `createAgentSession(...)` | 装配 agent + 工具 + 记忆 |
| 提问 | `session.prompt("...")` | 让它干活 |

拼起来大致是：

```
const runtime = ModelRuntime.create({ ... })
const session = createAgentSession({ runtime, ... })
await session.prompt("帮我做件事")
```

这就是"你自己的 Pi"的最小骨架。往里加工具、加扩展、改提示词，就长成了你想要的样子。

不用从零摸索，官方 [SDK 教程](https://github.com/earendil-works/pi/tree/main/packages/coding-agent/examples/sdk)就是 13 个递进的例子，正好踩着这本书的脉络：

照着走一遍，你就从"会用 Pi"变成"会造 Pi"了。

## 带走的设计智慧

这本书讲的是一个项目，但值得带走的是**一套设计观**。回顾全书，Pi 反复演示了这几条：

**表13-3 六条可复用的设计智慧**

| 智慧 | 出自哪 |
|---|---|
| 核心要小，其余交给扩展 | 第 1 章 |
| 敢"不做"，每条不做都留活路 | 第 1 章 |
| 统一层屏蔽差异（一套话对 30 家） | 第 4 章 |
| 异常是信息，不是终点 | 第 4、6 章 |
| 可选能力单独成包，核心不背重依赖 | 第 3、7 章 |
| 把"过程"拆成事件，才谈得上可控 | 第 5 章 |

这些不止适用于 agent——它们是"怎么把一个复杂系统做小、做开放、做得可接管"的通用答案。

## 后记

写这本书的初衷，跟写上一本一样：**把"看起来很玄"的东西，讲成"原来如此"。**

Pi 最打动人的，不是它有多强，而是它的一种**克制**——敢于只给四个工具，敢于把选择权完完全全交给你。在人人抢着"什么都内置"的年代，这种"少即是多"的勇气，反而成了它最鲜明的辨识度。

愿你在组装自己的 Pi 时，也带走这份克制。
